Clean Architecture & Layer Separation

The application is architected around Feature-Driven Clean Architecture with unidirectional state flow. This design pattern enforces strict boundaries between Presentation, Domain, Data, and Core service layers.

System Data Flow

[User Voice / Text Input]
          │
          ▼
   [SttService / Speech] ──► Transcribes to Text
          │
          ▼
   [VoiceChatBloc] ──► Emits Processing State & ChatGPT Loading Bubble
          │
          ▼
   [AiService (Interface)]
     ├──► [HybridAiServiceImpl] (Google Gemini 1.5 Flash Online LLM)
     └──► [LocalRuleAiServiceImpl] (Zero-Config Deterministic Rule Engine)
          │
          ▼
   [Parsed Intent Payload & SearchCriteria]
          │
          ▼
   [FlightSearchService] ──► Filters & Sorts 200+ Mock Dataset Flights
          │
          ▼
   [UI Render] ──► Dynamic Flight Cards, Badges, TTS Audio Output & Ticket View

Detailed Layer Responsibilities

1. Core Services Layer (lib/core/)

Contains centralized utilities, constants, theme tokens, and global service contracts:

  • ServiceLocator: Initializes global singletons and dependencies.
  • AiService: Interface defining prompt parsing contracts.
  • SttService & TtsService: Audio input and playback abstractions.

2. Domain Layer (lib/features/flight_booking/domain/)

Holds application entities and business use cases without Flutter UI dependencies:

  • SearchCriteria: Immutable entity maintaining origin, destination, date preferences, budget, direct-only flags, and sorting.
  • DateResolver: Converts natural date expressions into concrete DateTime ranges.
  • FlightSearchService: Performs filter evaluations and smart badge generation.

3. Data Layer (lib/features/flight_booking/data/)

Handles data fetching and mapping:

  • FlightLocalDataSource: Mock dataset provider containing 200+ realistic flights across international hubs.
  • BookingLocalDataSource: In-memory store for active passenger bookings and ticket confirmations.

4. Presentation Layer (lib/features/flight_booking/presentation/)

Handles reactive UI rendering and state management:

  • VoiceChatBloc: Controls listening state, partial recognition text, AI messages, and thinking loading bubbles.
  • BookingBloc: Controls booking confirmations, passenger details, and digital ticket creation.
